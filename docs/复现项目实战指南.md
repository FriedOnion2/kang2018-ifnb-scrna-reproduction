## 2. 项目目录骨架（GitHub 标准）

```
repro-<paper>/
├── README.md           # 门面：是什么/怎么跑/复现了什么
├── LICENSE             # MIT 或 Apache-2.0
├── .gitignore          # 排除数据、产物、缓存
├── data/               # README 记录来源+下载+MD5；原始文件不入库
├── scripts/            # 原子步骤，按 01_/02_/03_ 编号
├── notebooks/          # 探索性分析
├── results/figures/    # 最终图——提交，是简历门面
├── envs/environment.yml# 环境锁定（可复现性的命脉）
├── config/config.yaml  # 参数集中管理
└── Snakefile           # 编排：一条命令跑到底（加分项）
```

## 3. 可复现性的三条命脉

1. **环境锁定**：conda/mamba + `environment.yml` 精确到版本，别用最新版「顺手装」。
2. **数据可溯源**：来源链接 + 下载命令 + **MD5 校验和**，别人能验证拿到一模一样的文件。
3. **一条命令复现**：用 Snakemake/Nextflow 编排，`snakemake -c all` 从下载到出图全自动。

> **简历卖点梯度**：
> 「我跑过分析」 < 「我做了可复现的脚本」 < 「我搭建了全流程可复现管线（环境锁定+编排+一键复现）」

## 4. 每一步的工程规范

### 4.1 初始化
```bash
git init
git config --global user.name "你的名字"
git config --global user.email "你的邮箱"
```

### 4.2 环境锁定
```bash
mamba env create -f envs/environment.yml
conda activate repro-kang
```
把版本**精确到第三位**（如 `r-seurat=5.0.1`），而非 `r-seurat`。

### 4.3 数据获取与校验
`data/README.md` 记录来源；下载脚本末尾 `md5sum > md5sums.txt` 并提交校验文件，
原始数据用 `.gitignore` 排除（GitHub 单文件 100MB 上限，大文件用 git-lfs）。

### 4.4 原子步骤 + 编排
每个脚本做**一件事**（下载/QC/聚类/差异），Snakemake 声明输入输出依赖，
这样：① 断点续跑；② 改参数自动只重跑受影响步骤；③ 评审者一眼看清流程。

### 4.5 README 六要素
1. 项目简介一句话
2. 复现的结论
3. 数据来源表
4. 环境安装
5. 一条命令复现
6. 与原文对照表（结论一致/不一致那一栏**一定要填**，这是复现的灵魂）

## 5. 单细胞分析的标准步骤（本仓库对应脚本）

| 步骤 | 脚本 | 关键点 |
|---|---|---|
| 数据加载合并 | 01_stim_vs_ctrl.R | Read10X + merge，加 condition 元数据 |
| QC | 02_qc_normalize.R | nFeature 阈值 + 线粒体比例（`^MT-`） |
| 归一化+高变基因 | 02 | NormalizeData + FindVariableFeatures(vst, 2000) |
| PCA/UMAP/聚类 | 03 | dims 1:30、resolution 0.5（**参数要有理由**） |
| 细胞注释 | 03 | 经典 marker 列表——**这是必须亲手核对的地方** |
| 差异表达 | 04 | FindMarkers：stim vs ctrl，按细胞类型分组 |
| 结果可视化 | 03/04 | UMAP by condition、ISG heatmap |

## 7. 高频面试问题（提前准备）

1. **你的复现和原文差异在哪？原因？** —— 复现的灵魂，必问。
2. **为什么 resolution 取 0.5？dims 取 1:30？** —— 证明懂原理。
3. **数据放大 10 倍，哪里是瓶颈？** —— PCA 之后是矩阵运算，内存是瓶颈。
4. **注释细胞类型时如何避免把聚类号当作细胞类型？** —— 用 marker，不用 cluster id。
5. **如何保证别人能复现你的结果？** —— 环境锁定 + 数据校验 + 一键编排。

## 8. 常见的坑（避雷）

| 坑 | 后果 | 对策 |
|---|---|---|
| 数据「available upon request」 | 项目卡死 | 选论文前先下数据确认 |
| 环境版本不锁 | 一年后自己都跑不起来 | environment.yml 精确到版本 |
| 原始数据 push 进 git | 仓库炸掉、push 失败 | .gitignore + git-lfs |
| 把 cluster id 当细胞类型 | 注释全错、结论翻车 | 用经典 marker 逐个核对 |
| 结果图不入库 | README 干巴巴、简历没门面 | results/figures 必须提交 |
| 不填「与原文对照」栏 | 复现沦为「跑通教程」 | 结论一致/差异逐条记录 |
